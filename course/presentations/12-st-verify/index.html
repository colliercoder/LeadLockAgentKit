The workflow · Granite Peak - Verify Caller

Two paths. send_code and check_code.

send_code
  • Makes a 6-digit code
  • Stores only a hash
  • Emails what's on file
check_code
  • Hashes what they read
  • Marks the call verified
  • 3 wrong: locked
Only your agents get in.
Leadlock.ai
Open it in n8n and you'll see two paths. send_code: find them, make a code, keep a scramble, send it. check_code: scramble what they read, compare, count the try. And right at the start, a secret header check, so nobody else can call it. send_code finds the customer on file, stores the hash for 10 minutes, and replies with the masked address, never the code. check_code compares, counts the try, and replies verified, or tries left. First node: a secret header check (X-Support-Key). Source: From the checklist: open Granite Peak - Verify Caller in n8n and find the two paths and the secret header check (X-Support-Key).

Every rule lives in n8n. The prompt can't change any of them. The scramble uses a secret only the workflow knows, plus the code, plus the call. Three tries, and asking for a new code doesn't buy more. And n8n doesn't keep run history for this one, so codes don't sit in logs. Detail: never anything the caller says; the agent gets d***@leadlock.ai back; scrambled with a secret and the call, 10 minutes; a resend never adds tries; verified for 60 minutes on this call; run history is off.
