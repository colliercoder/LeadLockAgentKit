"I've got d***@leadlock.ai on file. I just sent you a 6-digit code." n8n makes the code, stores only its hash, sends it only to what's on file. The caller reads it aloud; n8n says verified or not.
Granite Peak proof, 2026-10-24: the reply carries a mask, never the code; sha256 of code + call, 10-minute expiry, 3 tries per call.
Caller wants their account. Joanne says: first, let me make sure it's you. n8n makes a 6-digit code, keeps only a scrambled version of it, and emails it to the address on file. Joanne never sees the code. She only hears back where it went. Caller reads it aloud, n8n checks it. Verified.
The rules · in n8n, not the prompt

Nothing to talk your way around.

Destination

Only what's on file

Nothing the caller says is ever where the code goes

The agent

Never sees the code

n8n replies with a mask: d***@leadlock.ai

Storage

Only a hash

Scrambled with the call, gone in 10 minutes

Guessing

3 tries per call

A resend doesn't reset them. Then the call locks.

Scope

This call only

Verified for 60 minutes, on this call

Logs

No copies

n8n doesn't save these runs

Why read it aloud: a text back goes to the text assistant, not the live call.
Granite Peak proof, 2026-10-24: execution saving off for the verify workflow; resend keeps the attempt count; locked calls refuse new codes and checks.
Leadlock.ai
Every rule lives in n8n. The prompt can't change any of them. Three tries, and asking for a new code doesn't buy more. Why not text it back? Inbound texts go to the text assistant, not the live call. So the caller reads it out.
