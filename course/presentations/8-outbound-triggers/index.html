The idea

Something happens. Your agent dials.

An outbound trigger is one request to Leadlock: which agent, which number.

The event: a form, a tag, a date

The trigger: one request

The call: your agent dials

agent_id
Which agent calls
to_number
Who it calls, +1 first
context
Name, source, notes. Optional.
Leadlock API: POST /outbound/trigger.
Leadlock.ai
Two fields are required: the agent and the number. Everything else is optional context for the agent. Same request no matter which tool sends it.

How it flows

Event in, result back.

Result back: post-call note and tags in GoHighLevel when connected, or your post-call webhook.
Leadlock.ai
Your tool only does the first step. Leadlock dials from the number assigned to the agent. After the call, the result goes back to your CRM or your webhook.
Before you start

Four things, once.

  1. Turn on outbound calling
  2. Agent set to Outbound or Both, with a number
  3. Copy the agent ID
  4. An API key, for n8n and webhooks
GoHighLevel shortcut

The Leadlock app action needs no key.

It knows your account from the connected GoHighLevel location.

Outbound terms opt-in, agent Setup tab Voice Direction, Settings > API Keys. The GoHighLevel app action finds your account from the connected location.
Outbound is off until you tick the box. Everyone misses it. Inbound-only agents refuse outbound calls. Copy the key once. You only see it one time.
The GoHighLevel way

Tag added, Leadlock calls.

Trigger: tag call-me-now

Webhook: call this contact

Remove tag call-me-now

Custom Webhook · POST
URL     https://leadlock-app.onrender.com/outbound/trigger
Header  X-API-Key: ████████
Body
{
  "customData": {
    "agent_id": "your-agent-id",
    "to_number": "{{contact.phone}}",
    "ghl_contact_id": "{{contact.id}}",
    "first_name": "{{contact.first_name}}"
  }
}

Any other system

  -H "X-API-Key: sk_live_████████" \

  }'
